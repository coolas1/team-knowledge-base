## Why

用户需要 Agent 在没有现成工具时自行创建能力，而当前产品仅开放固定 TKB 工具和技能读取，既不能执行自己编写的程序，也不能保存并复用生成的工具。日期、计算和网页处理只是验收示例，逐项内置这些功能无法覆盖后续未知任务。

本提案替代用户已驳回的 `fix-pi-agent-runtime-tools` 固定工具清单方案；后者不作为本次实施依据。

## What Changes

- 向 Web Agent 提供少量通用入口：执行代码、检索工具库、发布工具版本、调用已保存工具。具体业务工具的代码、参数 schema 和测试由 Agent 在任务过程中编写。
- 建立“检查已有能力 → 编写程序 → 试运行 → 根据真实错误修正 → 完成任务 → 保存可复用工具”的循环，在部署已授权范围内自动进行，不要求开发者为每种工具修改代码或用户逐个确认。
- 为生成程序提供独立任务执行环境，支持 JavaScript 标准库、系统时钟、临时文件和受控公网请求；隔离产品代码、密钥、会话存储及宿主机管理权限。
- 建立持久工具库，保存名称、描述、输入/输出契约、源代码、版本、运行时要求和实际测试结果，支持后续会话发现、调用、修复及停用版本。
- 修正现有 Pi 错误标志传递，统一生成、测试和调用预算；界面显示真实执行、修复、保存和复用过程，健康信息报告执行后端能力和不可用原因。
- 调整 Agent 提示词和技能：基础能力缺失时主动尝试构建；缺少外部凭据、运行环境或授权时如实说明，不能声称通过生成代码获得了不存在的权限。

## Capabilities

### New Capabilities

- `agent-tool-authoring`: Agent 按需编写、执行、修复、验证、保存和复用工具的完整行为，以及隔离、限额、错误和可观测性要求。

### Modified Capabilities

无。当前 main specs 没有对应能力。保留既有 TKB 和会话记忆接口，本次只在 Web Runtime 中接入自主工具能力。

## Impact

- `src/extensions/pi-agent/`：新增通用入口、执行后端客户端、工具库和 Agent 指引；修改 Runtime 预算、错误事件、健康信息和测试。
- 新增独立执行服务及任务镜像，接入 Compose；生成代码始终在任务环境运行，不 import 到 Pi 主进程。
- SPA 的工具活动展示、SSE 兼容字段，配置示例和部署说明。保留用户现有 Compose 修改。
- 工具库使用独立持久卷，不写入项目源码或直接变更 Engine 数据库。首版按当前单团队部署共享工具库，生成工具参数化，禁止把密钥或会话数据硬编码进共享实现。
- 不预置日期/计算/单位转换业务工具，不强制绑定搜索提供方，不开放产品源码编辑；外部服务仍使用实际可用的授权与凭据。
