## Context

动机见 proposal.md。现实现位于 `src/engine/hindsight_components/`，并非旧说明中的 memory 目录。retain 以文档替换结束，归纳仅处理本次事实；recall 已有四路检索、MMR、阶段期限和 trace；reflect 为一次规划后的有限子查询。Pi runtime 入队异常被忽略，而服务端队列已有租约和退避。现有 conversation-memory 规范要求旧请求默认团队共享。

上游参照：`../../hindsight/hindsight-api-slim/hindsight_api/engine/` 下 retain/orchestrator.py、entity_resolver.py、consolidation/consolidator.py、reflect/tools_schema.py、memory_engine.py。实施前记录实际版本和工作区差异，不把上游提示词存在视为效果保证。

## Goals / Non-Goals

**Goals:** 在当前引擎内实现可独立开关的生命周期服务；所有批次均保持旧 API 默认行为；功能完成和效果通过分别记录。

**Non-Goals:** 不引入第二套 Hindsight 服务作为存储真相，不替换现有知识库引擎，不推断旧共享数据的用户归属；不以此变更实现全量上游 SDK/集成兼容。

## Decisions

### 1. 七批交付与依赖

| 批次 | 修改重点与位置 | 前置 | 可独立验收的交付 |
|---|---|---|---|
| B1 范围与基线 | types/protocols/models/repository、interface、配置、graph 查询；建立对照数据 | 无 | 默认共享兼容；隔离及标签语义覆盖所有读取路径 |
| B2 可靠保留 | Pi runtime/会话持久化、queue/worker、retain、实体与文档版本 | B1 | 服务不可用和重启不丢投递；身份时间正确；增量与实体案例通过 |
| B3 持续归纳 | 新 consolidation worker、observation/history/evidence、删除与图 outbox | B1+B2 | 多轮归纳、精确/语义合并、历史及删除竞争通过 |
| B4 检索与证据 | recall/service/interface/MCP、expand 与 freshness、注入格式 | B3 | 请求过滤和预算贯穿各分支；过期及原文展开可验证 |
| B5 长期模型 | model 服务、调度器、版本、来源依赖及管理 API | B3+B4 | 手动/事件/定时刷新、增量更新、失败保留及删除传播 |
| B6 动态推理 | reflect 工具循环、引用校验、directive/profile 配置 | B4+B5 | 按工具结果再次规划；过期回查；预算终止和引用有效 |
| B7 管理与验收 | BFF/前端、CLI/MCP 管理、诊断、对照报告 | B1-B6 | 从轮次追到任务与证据；全场景回归和迁移演练 |

每批可拆多个小 PR，但共享本 change 的批次任务编号；未完成七批不归档整项变更。每批提交验收记录后再推进下一批，失败先修复。这里不要求每个小步骤再次审批，也不自动授权上线。功能开关按批次依赖启用，不能在 B1 过滤未通过前启用隔离范围。

用户于 2026-09-09 要求按七部分分别保存提交：后续每批验收完成后创建本地 Git commit。当前 B1 与部分 B2 已交织的工作先保存为阶段性提交，明确 B2 尚未验收；不将该提交视为 B2 完成，也不自动推送或部署。

### 2. 保留存储，增加明确范围

使用服务端 `MemoryScope`（bank_id、allowed tags、主体/Agent 身份和策略版本）。所有公开入口解析一次范围，内部调用强制传递；旧调用映射到 default-team。新增表包括 banks/scope 配置；已有 memory/entity/link/job/model 记录补 bank 字段并使用范围内唯一约束。Neo4j 投影和查询同样携带 bank，不能只过滤最终 top-k。

标签不是身份认证。MCP/BFF 根据已有可信调用上下文和服务配置验证可用范围，模型生成的 bank/tag 不能扩大权限；暂未配置身份映射时只允许共享默认范围。session 标签仅表示来源；用户/项目归纳范围由受信任配置指定。采用上游的 any/all/strict/exact 语义，组合过滤在入口标准化成同一表达式。

替代方案：仅加 session_id 过滤不能支持跨会话认识；全局归纳后再裁剪可能泄漏，均不采用。

### 2.1 Pi 会话范围（已批准并入 B1）

BFF 验证并只转发可信范围凭据，Pi 使用同一服务端 MEMORY_SCOPE_BINDINGS 映射再次验证。完整绑定的规范化指纹决定独立会话、transcript 和工具库目录；凭据本身不落盘，也不进入提示词或工具参数。无凭据和完全默认绑定沿用旧目录；不从会话文本推断身份。相同绑定轮换凭据保留目录，改变绑定会进入新的命名空间，不能自动取得旧会话。

每个范围运行时只枚举自己的目录，每个会话持有独立 MCP 客户端及记忆注入扩展。历史读取、消息、取消和删除在流开始/操作前检查归属；持久化归属标记在普通删除后保留，以允许原范围显式遗忘长期记忆。服务重启恢复同一命名空间。配置或凭据撤销通过服务重启生效，BFF 仍按当前功能开关拒绝未启用范围。

B1 验收纳入任务 1.12：交叉范围、同 bank 不同绑定、未知凭据、重启、凭据轮换、默认旧历史及删除后遗忘。B2 的补投可靠性要求不因本项提前接入范围而视为完成。

### 3. 投递意图与处理结果分开

经用户批准，B1 同时迁移 documents/chunks 的归属：文档是范围的权威来源，chunk、记忆及图投影继承该范围；旧记录为 default-team。文档列表、详情、原文、编辑、重入库、删除和普通 GraphRAG 召回均执行范围检查，关联文档和图实体描述也不能跨范围聚合。后台任务携带已解析的范围，不能恢复成默认全局。文档访问失败沿用不存在语义，不返回其他范围原文或元数据。B1 的验收包含任务 1.9–1.11，后续批次等待这些入口一并通过。

在已完成轮次持久化边界记录稳定 delivery intent。优先同事务写入；若当前会话存储不能与队列原子提交，则在同一持久化会话事件中记录待投递标记，由可恢复扫描器重放，不依赖易失内存回调。键为 scope/session/turn，内容版本冲突显式报错，收到 durable acceptance 才标记已投递。

引擎 job 使用租约、续租或 fencing token、退避和有限重试，防止过期 worker 覆盖新任务。统一 operation 基础在 B2 引入，管理 UI 留到 B7。抽取 success/empty/degraded/failed 与投递 accepted 分开；保存原文允许降级，但仍保留可补偿阶段，不再静默完整成功。

替代方案：简单增加 Pi try/catch 日志不能补投；直接同步等待所有记忆处理会增加聊天延迟。

### 4. 保留事实来源，增量修改文档

retain 输入增加可选说话者身份、source timestamp、reference timezone、策略版本及 update_mode。严格验证抽取类型和时间；错误 payload 不降成正常 world 事实。实体解析先范围内规范名/别名候选，再用上下文判定，不确定时保留分立；纠正记录能重建关联。

文档记录 revision 与请求幂等键，chunk 内容指纹与抽取策略版本联合决定是否复用。append 只应用一次，replace 只失效变更部分，使用锁或乐观版本避免覆盖。来源引用基于稳定 chunk/fact ID，不基于会变化的位置编号。更换抽取策略需要明确再处理而不能错误复用缓存。

### 5. 独立持续归纳和证据依赖

事实提交同时产生 consolidation outbox。按 bank+write scope 分批取未处理版本，读取相关已有 observation 和源事实，生成经过 schema 验证的 create/update/delete 动作。持久化 observation、版本快照、证据边和处理游标原子提交；scope 锁加版本检查防止多 worker 丢更新。LLM 调用不持有长数据库事务，提交前重新验证来源及目标版本。

精确归一化去重先执行；语义近邻达到可配置阈值后再做等价判定，创建和更新路径都覆盖；不能仅按相似度合并矛盾。合并保留有效证据并更新向量/图 outbox。配置 scope 容量、批量、最大轮数、并发和费用上限，超额继续排队或报显式状态。

新增通用 derived-source 依赖关系，支持 observation 和 model。源删除/替换事务内立即标记相关派生内容不可用并发出重算任务；模型生成期间重新校验源版本和删除 tombstone。无有效来源删除派生内容，有剩余来源重算；历史管理界面不得展开已遗忘原文。所有读取先检查可用状态，不能等待 Neo4j 最终一致完成才生效。

替代方案：每轮重算整个 bank 成本过高；简单 latest-wins 无法解释历史与真正矛盾。

### 6. 复用检索预算，扩展参数和工具

复用现有 DeadlineBudget、MMR 和多路融合，增加请求类型/标签/时间/include/min_scores/prefer_observations。请求预算不能提高服务器硬上限。expand 单独检查范围、来源有效性与 token 上限。候选提供 retrieved provenance、updated_at、stale reason；注入可展示类型和时间，默认仍保持 bounded fast 行为。

Reflect 保留旧流程作为开关回退，新增 search_mental_models/search_observations/recall/expand/done。新循环以全部工具和 LLM 调用共享总期限、总 token、最大迭代，遇到工具失败保留可用证据而非无限重试。没有 raw recall 结果时仍可搜索有效 model。done 输出分离 actual citations 与 retrieved candidates，校验 ID/类型/范围；校验失败仅允许预算内一次修复，仍无效则明确不足。

### 7. 明确定义模型再刷新

Mental model 必须先创建（问题、范围、输出结构、token 上限、触发器）；不自动凭空生成用户画像。支持手动、归纳完成事件和 cron/间隔调度，按 model+source watermark 合并任务。版本采用 compare-and-swap 发布，失败保留最后成功版本但标 stale。结构化 delta 按 schema 校验，无法安全应用则完整刷新，禁止失败结果覆盖正确版本。

Directives 独立于普通事实，只有管理入口可修改，按 scope/触发规则加载；LLM 引用的历史命令不升级成 directive。

### 8. 验收阈值与记录

B1 固定至少 40 个标注案例（归属、跨轮、重复、变化、隔离、时间、追加、删除、故障、模型及推理每类至少 3 个，类别可交叉），为每批指定子集。固定数据、模型和配置，上游/TKB 默认各跑 1 次并记录环境；仅在具体失败或新风险需要时追加定向验证，不重复全量评审。用户于 2026-09-09 明确要求减少验证/评审轮次、优先实施效率，该要求取代原来的固定三次规则。确定性检查（范围、引用存在、幂等、删除、故障恢复）必须全通过；标注语义正确率每类不低于 90%，且比相同设置的上游均值低不超过 5 个百分点。未达标报告差距，不通过降低门槛宣称对齐。

LLM 评测记录输入/输出摘要、人工可复核判定、p50/p95、token/成本与失败率，敏感原文不进入常规日志。各批必须通过相关单元/契约测试；涉及数据库、图或 worker 的批次完成真实隔离测试环境的故障/并发验证。提交前按项目要求 lint+pytest，前端变更运行 npm test。无法运行真实依赖或上游时标为待验证，不将批次验收勾选完成。

## Risks / Trade-offs

- 范围字段回填不完整 → additive 迁移、default-team 回填计数核对，隔离流量必须等待约束及过滤验收。
- 语义合并误伤 → 等价判定、证据快照、冲突集、可重算；不以 embedding 阈值单独决定。
- 归纳和刷新放大费用 → scope 容量、任务合并、批量/并发/预算硬限制和死信诊断。
- 新旧代码共同写入破坏范围 → 每批明确支持的部署版本；启用新范围后不允许无范围旧 worker 继续消费。
- 上游版本变化 → 本变更锁定本地基线，升级上游另记差异，不移动验收目标。

## Migration Plan

1. B1 添加可兼容表/字段/索引及默认范围，保存迁移前计数；分段回填、断点续跑、核对孤立链接，暂不开隔离功能。
2. B2 开启新投递通道与操作状态；扫描已保存完成轮次时沿用稳定 ID，历史补投显式选择起点，不盲目重新写入全部历史。
3. B3 为旧事实建立待归纳游标，旧单次 observation 作为可重建派生数据；灰度范围开启新归纳，同时关闭该范围旧同步归纳，避免双写重复。
4. B4-B6 先只读影子比较，再对指定测试范围启用；派生数据可从事实重建。每批输出迁移和回滚演练结果。
5. B7 经现有 CI/CD 管线发布，禁止手工操作 LAN compose。规划完成本身不代表已经发布。
6. 回退使用仍支持 scope 和删除 tombstone 的兼容版本，关闭新推理/刷新/归纳开关，保留待办任务与历史，不删除新表。开启隔离后不可退回无范围读路径；需要暂停隔离入口而不是读取全局数据。
