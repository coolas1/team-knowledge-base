## Purpose

Provide visually coherent image-based presentations from authorized knowledge sources through a staged, reviewable workflow, with persistent progress, bounded model usage, recoverable page generation and trustworthy downloadable PPTX artifacts.

## ADDED Requirements

### Requirement: Image presentations preserve existing document behavior
The system SHALL expose image-based PPT as a distinct workflow while preserving existing DOCX, PDF and ordinary editable PPT generation. It MUST disclose that image-slide elements are not individually editable and SHALL NOT claim an outline file is an editable equivalent.

#### Scenario: Existing document tool is called
- **WHEN** a client uses the existing document generation contract
- **THEN** its response schema and ordinary output behavior remain compatible

### Requirement: Outline and sample approval gates
The system SHALL require explicit approval of the outline, style and configured backend before generating one sample, and approval of that sample before generating remaining pages. Approval MUST bind to the current revision; material style/backend changes SHALL invalidate sample approval.

#### Scenario: Sample has not been approved
- **WHEN** the remaining deck is requested before sample approval
- **THEN** no remaining-page image calls are dispatched

#### Scenario: Stale approval arrives
- **WHEN** approval refers to an older revision
- **THEN** the system rejects it and presents the current review state

### Requirement: Compatible generation backend and source assets
Final slides SHALL be generated by the configured image backend using validated capabilities, not placeholder screenshots. Required reference images MUST be transmitted to the backend. Upstream skill origin, pinned version and workflow adaptations SHALL be recorded and available for review.

#### Scenario: Provider cannot accept a required image
- **WHEN** a page requires an original figure that cannot be supplied to the backend
- **THEN** that page is blocked with a specific reason rather than silently generated from text alone

### Requirement: Durable asynchronous generation
Creation and control requests SHALL return promptly with a task identity. Page progress, approvals, artifacts and errors MUST survive client disconnection and worker restart. Expired workers MUST NOT overwrite current revisions. Successful unchanged pages SHALL be reused during resume.

#### Scenario: Restart after a page is persisted
- **WHEN** the worker restarts before the next page completes
- **THEN** the stored successful page is reused and only unfinished eligible work resumes

#### Scenario: Provider outcome is unknown
- **WHEN** the connection fails after submission and provider success cannot be established
- **THEN** the page is marked unknown and is not automatically resubmitted as though no charge occurred

### Requirement: Scope applies throughout presentation lifecycle
The system SHALL enforce trusted bank/tag permissions for sources, creation, approval, task status, reference assets, cache reuse, execution and download. Credentials MUST remain server-side. Source or authorization changes SHALL prevent further unauthorized generation and access.

#### Scenario: Another bank requests a task
- **WHEN** a caller outside the task scope requests its status, preview or artifact
- **THEN** access is denied without exposing private content

#### Scenario: Source permission is revoked
- **WHEN** a queued task loses access to a required source
- **THEN** further generation is blocked and existing private materials are not served to the revoked caller

### Requirement: Bounded generation and cancellable work
The system SHALL bound page count, model attempts, repairs and concurrency; atomically reserve configured budgets before dispatch; include retries in accounting; and display unknown billing values explicitly. Cancellation SHALL prevent new calls and final success publication while retaining accurate accounting for in-flight work.

#### Scenario: Budget is exhausted
- **WHEN** the next page would exceed the configured budget
- **THEN** the job pauses before that provider call and can resume only with an explicitly changed budget or eligible cached result

#### Scenario: User cancels during generation
- **WHEN** an in-flight task is cancelled
- **THEN** no additional pages start and any late result cannot mark the task completed

### Requirement: Visual verification and artifact integrity
Each page SHALL pass structural and visual checks for content, readable text, numerical fidelity, required assets and style before assembly. The system SHALL produce the expected page count, speaker notes and a valid PPTX, publish only verified artifact paths, and expose failed-page reasons and bounded repair actions.

#### Scenario: A page fails visual checks
- **WHEN** required text is missing or figures are incorrect
- **THEN** the page remains unaccepted and the deck is not reported as complete

#### Scenario: Final download is offered
- **WHEN** a job is completed
- **THEN** the PPTX exists, opens with the expected slides and notes, and its download uses current authorization

### Requirement: Acceptance uses real bounded provider evidence
Before production enablement the workflow MUST pass a bounded synthetic deck test through the actual application entry point, including sample approval, reference imagery, interruption/resume and download verification. Reports SHALL separate mocked fault tests from real provider outcomes and SHALL NOT infer image quality parity from transport success.

#### Scenario: Only mock generation has passed
- **WHEN** tests use placeholder provider results and no real Seedream output
- **THEN** end-to-end production acceptance remains incomplete
