核心发现

✓ csv/xlsx 提取器是最大功臣，多模态 0.50 → 0.73

新增结构化键值对表格提取器后，6 道原本 "NOT FOUND" 的表格题全部救回：

  • Q14 月度储蓄为负 → finance-2024.csv ✓
  • Q15 RYK-03 季度白化最大 → bleaching-survey-2024.xlsx ✓
  • Q24 全站点最高 SST → SST_2024_monthly 表 ✓
  • Q27 最高平均评分发酵类型 → batch-log.xlsx ✓
  • Q28 批次 B-013 三方冲突 → batch-log.xlsx + ph-readings.csv ✓
  • Q02 最长曲目 → tracklist.csv（0.5→1.0）✓

✓ 迭代多跳救回 Q04（多约束细节题）

Q04「最深典型潜水点」需要在多个站点约束间交叉验证，2 轮实体锚点检索把它从 0.0 提到 1.0（正确识别 RYK-10 Kerama Outer）。

✓ 修复了一个既有 bug：Neo4j 标签未清洗

LLM 抽出的实体类型含空格（如 "Site Name"）会导致 Cypher 语法错误，使整个文档索引失败。新增 _sanitize_label 后 bleaching-survey 等多 sheet 表格顺利入库。

✗ Q07/Q22 回退：多模态 reranker 固有限制

专辑封面 album-cover.png 的 VLM 描述文本被 reranker 打 0.000 分——模型本身不认为图片描述与「封面三行文字」查询相关，导致图片文档排到第 47 位，进不了 top-12。这是 reranker 模型对图片查询的判断，检索架构无法修复，需换更强的多模态 reranker 或 agentic 重检索。

△ 仍存在运行间抖动（LLM 非确定性）

Q05/Q06/Q20 在不同轮次间于 0.5↔1.0↔0.0 波动（作答与评判均为 qwen-plus，temperature 虽低仍有抖动）。这提示对关键题应多次采样取众数，或固定随机种子。

△ 剩余硬骨头

  • Q13（三条件潜点）：多约束仍未串全，0.0
  • Q23（散点图 R²）：VLM 读图 0.47 vs 真值 0.66，0.0
  • Q29（expenses.csv 求和）：表格已入库但 LLM 未对 19 行求和，0.0

下一步建议

1. 多模态 reranker 升级

Q07/Q22/Q23 的根因是 reranker 对图片/图表查询打分失真。换用多模态 reranker（如 qwen3-vl-rerank）或对图片 chunk 做查询感知的分数校准。

2. 表格聚合能力

Q29 需要跨行求和。可在表格提取时预计算常用聚合（sum/max/mean）写入 chunk，或让作答 agent 调用代码工具处理表格。

3. 稳定化

对作答与评判固定随机种子 / 多次采样投票，消除 Q05/Q06/Q20 类抖动，让分数可复现。

4. 深度多跳

Q13 需 3 条件交集。可引入约束分解：把多约束查询拆成子查询分别检索再求交集。
