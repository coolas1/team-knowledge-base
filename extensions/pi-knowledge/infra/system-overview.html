pi-knowledge 系统架构总览

存储 · 检索 · 维护 — 三大子系统概览

存 存储侧
基础设施与数据形态

基础设施：向量数据库（ParadeDB / pgvector）+ 图数据库（Neo4j）

存储内容：多模态文档 + 记忆原文（会话） + 长期记忆

三类数据形态：

形态含义示例
原始格式用户放入 vault 的源文件.pdf / .docx / .pptx / .xlsx / .jsonl
中间形态统一转 md 方便 LLM 语义理解；所有切分、向量化入口均从 md 开始.derived/*.md（影子文件）；会话保持 jsonl
系统形态入库后的可检索结构向量（chunks.embedding）+ 图（Neo4j 节点/边）
三类内容的存储方式
  • 多模态文件 — 代码解析转 md → 切分 → 存入向量 + 图数据库
  • 记忆原文（会话） — 用户 /quit 结束会话时触发存储：对话切分后存入向量 + 图；继续之前会话时，增量更新最后一个 chunk
  • 长期记忆 — 记录用户事实/决策/经验/偏好，保存为 md 文件；作为系统提示词注入，同时入向量 + 图与其它信息建立联系
向量数据库（6 张表）
  • documents — 文档元数据（记忆也作为文档存储）
  • chunks — 正文 + 标题 + embedding + doc_id 外键
  • graph_jobs — 图谱构建任务队列
  • entity_vectors — 图结构实体表
  • relation_vectors — 图结构关系表
  • index_meta — KV 配置（embedding 维度等）
chunks 表含两类索引：BM25 全文索引（jieba 分词）+ HNSW 向量索引（cosine）
图数据库（Neo4j）

节点 5 种：

Doc · Dir · Month · Entity · Community

边 6 种：

IN_DIR · MODIFIED_IN · MENTIONS · REL · IN_COMMUNITY · DOC_REL

图中存储的是三元组（头节点, 边, 尾节点）；关系边附带文档/chunk 来源，一个关系只来自一个文档
Chunk 切分策略

目标 ≤800 字符，overlap = 150；超 1600 字符递归降级到句号/感叹号/问号切分。

按标题行切章节→ 章节内按空行切段落→ 贪心聚合到目标大小→ 超长递归切分
图构建流程
预定义节点/关系类型→ 全量扫描文档→ LLM 文档级抽取→ 写入 Neo4j→ 向量库建实体/关系表→ 社区摘要
  • 关系中附带文档/chunk 来源（非节点附带），一个关系只来自一个文档
  • 对节点密集区域（"社区"）生成一套 LLM 摘要
检 检索侧
架构

主 agent 与用户对话；触发存检功能时，启动 subagent 执行检索，结果返回主 agent，保持对话上下文整洁。

检索管线
#阶段说明
1Query 改写/扩展子 agent 深度检索模式才有；快查模式直接用原始 query
2三路并行召回BM25 + 向量 + 图（权重 1 : 1 : 0.5）
3RRF 融合粗排多路信号交叉打分，图谱路衰减 0.5
4Reranker 精排规划中，cross-encoder 对 top-N 重排
5全文补读对关键命中 read_doc 读全文，避免片段误判
6LLM 生成答案子 agent 预算：最多 15 次工具调用
图检索流程
jieba 分词→ Neo4j 匹配实体名→ 未命中? fallback 向量搜实体描述→ MENTIONS 边定位文档+chunk→ 1 跳关系遍历扩展→ ParadeDB 拉取 chunk 原文
  • 分词是轻量 jieba 切词，非 LLM 提取实体
  • 精确匹配 + 包含匹配；fallback 向量相似度 > 0.3 才取
  • 每文档最多 3 个 chunk，总上限 15
维 维护侧
文档维护 确定性管线

ingestVault + processGraphJobs：vault 增量扫描 → 摄取 → 图谱异步消费 → 消失清理，全程无 agentic 循环。

  • SHA256 短路 — 源文件字节哈希与 documents.content_hash 比对，未变则跳过
  • ingestFile — 转影子 md → chunkMarkdown 切分 → embed → 单事务写入（documents UPSERT + chunks 全删重建 + graph_jobs 置 pending）
  • processGraphJobs — 认领 pending（limit=200, FOR UPDATE SKIP LOCKED）→ 清旧派生边 → 结构边 → LLM 抽取 → 语义边 → entity/relation 向量 MERGE；失败 <3 次回 pending，≥3 标 failed
  • removeDocument — vault 中消失的文件：DELETE documents（级联 chunks）+ 删影子 md + 删 Neo4j REL 边 + DETACH DELETE Doc 节点
  • cleanupOrphanNodes — 无连接 Entity 删除，Dir/Month 级联循环删
  • normalizeRelations — 硬编码字典（18 条）把中文自创关系类型批量映射回标准大写类型
  • refreshCommunities — Union-Find 连通分量（≥3 成员）→ LLM 摘要 ≤300 字 → 先清后建 Community 节点 + IN_COMMUNITY 边
记忆维护 agentic 循环LLM + function calling

maintainMemories：把全部 active 记忆列表交给模型，模型通过 4 个工具自主决策：

  • memory_read — 读全文核实
  • memory_update — 合并要点到保留条目
  • memory_supersede — 标记被取代（不删文件，退出注入视图）
  • memory_delete — 彻底删除文件 + 索引 + Neo4j 节点
图谱维护 agentic 循环LLM + function calling

maintainGraph：把全部实体列表交给模型，3 个工具：

  • graph_entity_docs — 核实两实体各自出现在哪些文档
  • graph_merge_entities — 合并重复实体（重定向 MENTIONS/REL 边，记入 aliases，删除 duplicate）
  • graph_link_docs — 建立文档间关系（如 UPDATES）
审计报告

生成结构化 markdown 报告写入 vault/maintenance/{timestamp}.md，并 ingestFile 入索引（报告本身也可被检索到）。同时更新 .derived/maintenance-state.json 记录最后执行时间。
