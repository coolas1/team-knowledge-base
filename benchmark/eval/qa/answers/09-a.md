# A09 — Sketch vs released track: BPM and key shift

## Answer

The sketch became **Track 2, "Polyp"**.

| Version | BPM | Key      |
| ------- | --- | -------- |
| Sketch (2023-11-15 journal) | 70 | F# minor |
| Released track (tracklist.csv / EP notes) | 72 | A minor  |

The released track is **2 BPM faster and a whole step lower** than the
sketch.

## Sources

- `raw/journal/2023-11-15.md` — "What came out: a 70 BPM loop in F# minor, just a sub-bass pulse and a filtered noise bed."
- `raw/music/polyp-tidal-ep-notes.md` §"Origin" — "The sketch was a 70-BPM loop in F# minor built around a single sub-bass pulse and the sound of a SCUBA inhale. That became track 2, 'Polyp'."
- `raw/music/tracklist.csv` row 3 (track_no=2) — `bpm=72`, `key="A minor"`.
- `raw/music/polyp-tidal-ep-notes.md` §T2 — "T2 — Polyp (72 BPM, A minor)".

## Reasoning

1. The journal names the sketch's tempo/key as 70 BPM / F# minor.
2. Both ep-notes §Origin and §T2 confirm the sketch became T2 "Polyp".
3. But the *release* version per tracklist.csv is 72 BPM / A minor — a deliberate change between sketch and release that the corpus documents but doesn't explain.

## Gotchas

**Documented inconsistency.** The sketch and the release have different
BPM and key. A retrieval agent that only reads the journal will report
"70 BPM / F# minor"; an agent that only reads tracklist.csv will report
"72 BPM / A minor". Both are correct in their respective source. The
complete answer requires surfacing both and noting the shift.
