## Which source does the temperature data support?

**The recipes.md / koji claim.** Koji requires 28–32 °C (per the recipe);
kimchi requires 18–22 °C. The ph-readings.csv B-013 time-series averages
~30.1 °C, which falls squarely in the koji range and is far too warm
for kimchi.

## Sources

  > "see batch B-013 in `ph-readings.csv`. The first attempt in 2023-06
  > failed due to a cold room (21 °C); see `batch-log.xlsx` B-002 notes."
- `raw/fermentation/batch-log.xlsx` `Batches` sheet row 14 (batch_id=B-013):
  `type=kimchi`, `start_date=2024-03-01`, `temp_c=21.4`, `vessel=clamp jar`,
  `rating_1to5=5`, `notes="salty, dilute next time"`.
- `raw/fermentation/ph-readings.csv` rows for B-013: 30 daily pH + temp
  readings from 2024-01-05 to 2024-02-03; temp_c values range from 28.6
  to 31.5 with mean ≈ 30.1 °C.

## Reasoning

1. The recipe file's koji section names B-013 as the representative
   batch in `ph-readings.csv`.
2. But `batch-log.xlsx` lists B-013 as kimchi (clamp jar, 21.4 °C, 10
   days — internally consistent with kimchi's recipe parameters).
3. The `ph-readings.csv` temperature time-series for B-013 averages
   ~30 °C — this matches the **koji** recipe (28–32 °C) and is
   incompatible with the kimchi recipe (18–22 °C).

So the prose (recipes.md) and the time-series data (ph-readings.csv)
agree on koji, while the row-level batch-log.xlsx is the outlier.

## Gotchas

**Documented 3-way inconsistency.** A retrieval agent that only reads
`batch-log.xlsx` will report "kimchi" and be confidently wrong vs the
other two sources. Full credit requires surfacing **all three** values
and noting which two agree.

The likely cause (visible only if you read the generator script) is that
the generator randomly assigns `type` to each batch row via
`RNG.choice(types)`, then the markdown prose was authored separately to
reference B-013 as a koji example. The random draw produced `kimchi` for
B-013 in the xlsx, but the prose was written against the koji intent.
The temperature time-series was hardcoded to koji temperatures
(`temp_center=30.0` for B-013 in `write_csvs`), so it sides with the prose.
